# Production deployment

Sentinel AI uses three independent managed services:

- Vercel serves the Next.js frontend.
- Render runs the FastAPI backend on its free web-service tier.
- Neon provides PostgreSQL.

No credential belongs in Git. Configure every secret in the provider dashboard.

## 1. Create the Neon database

1. Create a Neon project in the Singapore region where available.
2. Copy the pooled connection string and replace `postgresql://` with
   `postgresql+psycopg://` so SQLAlchemy selects the installed Psycopg 3 driver.
3. Keep `sslmode=require` in the URL.
4. Save the result as Render's `DATABASE_URL` secret.

Example shape only:

```text
postgresql+psycopg://USER:PASSWORD@HOST/DATABASE?sslmode=require
```

## 2. Deploy FastAPI on Render

1. In Render, create a Blueprint from this GitHub repository.
2. Render detects [`render.yaml`](../render.yaml).
3. Enter `DATABASE_URL`, `CORS_ORIGINS`, and the SMTP values when prompted.
4. Use the public Vercel origin for `CORS_ORIGINS`, with no trailing slash.
5. Confirm the pre-deploy migration succeeds.
6. Confirm `https://YOUR-RENDER-SERVICE.onrender.com/health` returns
   `{"status":"ok"}`.

The free deployment stores uploaded source files and generated PDFs under
`/tmp/sentinel`. Render may clear this filesystem during restarts or redeploys.
Imported business records, accounts, audit data, and metadata remain persistent
in Neon PostgreSQL. Upgrade Render and attach a persistent disk before treating
file retention as a production guarantee.

## 3. Deploy Next.js on Vercel

1. Import the GitHub repository in Vercel.
2. Set **Root Directory** to `frontend`.
3. Keep the detected Next.js framework settings.
4. Configure both environment variables for Production, Preview, and Development:

```text
NEXT_PUBLIC_API_URL=https://YOUR-RENDER-SERVICE.onrender.com/api/v1
API_INTERNAL_URL=https://YOUR-RENDER-SERVICE.onrender.com/api/v1
```

5. Deploy, then copy the production Vercel origin back into Render's
   `CORS_ORIGINS` and redeploy the backend.

## 4. Configure email

Registration and OTP login intentionally fail closed when SMTP is unavailable.
Set these Render secrets using a real transactional email service:

```text
SMTP_HOST
SMTP_PORT
SMTP_USERNAME
SMTP_PASSWORD
SMTP_USE_TLS
SMTP_USE_SSL
EMAIL_FROM
```

## 5. Production verification

Run this acceptance path with two organizations:

1. Register and verify Organization A.
2. Upload a valid CSV and verify its dashboard, Sentinel answers, and PDF.
3. Sign out and verify the session cookie is removed.
4. Register Organization B and upload a different CSV.
5. Confirm its metrics differ and that Organization A asset identifiers return
   `404` or `403` while authenticated as Organization B.
6. Check Render logs for unhandled errors and Neon monitoring for failed queries.

## Hosted environment variables

| Service | Variable | Secret | Purpose |
|---|---|---:|---|
| Render | `DATABASE_URL` | Yes | Neon pooled SQLAlchemy URL |
| Render | `JWT_SECRET_KEY` | Yes | JWT signing key; generated by Render |
| Render | `CORS_ORIGINS` | No | Exact Vercel origin |
| Render | `STORAGE_ROOT` | No | Persistent disk mount |
| Render | SMTP variables | Yes/No | Real email and OTP delivery |
| Vercel | `NEXT_PUBLIC_API_URL` | No | Browser-to-API URL |
| Vercel | `API_INTERNAL_URL` | No | Next.js server-to-API URL |

Rotate `JWT_SECRET_KEY`, database credentials, and SMTP credentials after any
suspected exposure. Rotation invalidates existing JWT sessions.
